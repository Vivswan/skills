# Retire Branch: why each gate exists

Companion to `scripts/retire-branch.mts`: the incidents behind its gates, one paragraph each, so a change to the script can be judged against what the gate was for.

- **One program, four exit codes.** `verify && delete` degrades to `verify; delete` the moment anything joins it with `;`, `|| true`, or a pipeline whose status comes from the wrong end; three landings in one session destroyed state their own check had refused. Exit 3 (broken measurement) is kept apart from exit 1 (refused): a refusal for the wrong reason is an unanswered question, and an unanswered question must never sit one `|| true` away from a deletion.
- **Fetch into a ref the run owns.** A remote-tracking ref is a cache: after a non-fast-forward rewrite, `origin/main` can still contain the branch and ancestry says "contained" about a history the mainline no longer holds; whether a fetch updates it at all depends on the remote's refspec. `FETCH_HEAD` is one slot every fetch in a shared worktree rewrites. The script fetches into `refs/retire-branch/<pid>/mainline`, clears that name with `--no-deref` first (a fetch force-updating a symbolic ref writes its target; verified, main lost a commit), and drops it on every exit path.
- **Ancestry: the argument order is the whole gate.** `git merge-base --is-ancestor <branch> <reference>` asks the right question; the swap exits 0 on exactly the unlanded work the gate protects, and both orders agree after a fast-forward merge, so the tests force an UNMERGED branch. One call site, named parameters; the UNMERGED scenario with its swapped-argument mutation is the proof.
- **Content equivalence settles squash and rebase merges.** The branch's shas never reach the mainline, so ancestry refuses every landed branch there. The paths changed since the merge-base are intersected, by raw bytes, with the paths that differ at the mainline tip: any intersection is a refusal naming the paths, an empty delta is a refusal (nothing to judge), a failed diff is exit 3. `--no-renames` keeps a missing deletion from hiding, `--no-ext-diff --no-textconv --no-relative --ignore-submodules=none` keep any filter or config from suppressing or narrowing a difference, and raw bytes keep a non-UTF-8 filename from being re-encoded into a path that does not exist (which would diff nothing and pass). A later mainline commit to one of the branch's paths refuses too; that is the fail-closed direction, settled by reading the mainline history, never by forcing the deletion.
- **A shallow clone can never refuse.** Git treats the grafted boundary as a root, so history it cannot see reads as "not contained" with a plain exit 1. That negative is exit 3, with `git fetch --unshallow` as the remedy.
- **Delete by explicit ref, pinned to the judged sha.** `git branch -D` deletes whatever the name points at now; `update-ref -d --no-deref <ref> <sha>` refuses a push that landed between the gate and the deletion. A symbolic branch ref is refused outright: `update-ref -d` dereferences by default and deleting `refs/heads/topic -> refs/heads/main` deletes main while every gate passes (verified). A failed deletion is classified: ref moved is exit 1 (re-run), ref unchanged is exit 3 (the write failed, not the lease), ref unreadable is exit 3. A dangling symref left where the branch was makes `show-ref` answer like a missing ref, so the postcondition also asks `symbolic-ref` before believing an absence.
- **Every fallible gate runs before the removal.** The first capture happens, then a fetch; the tree can switch branches, commit, acquire work or a stranger in that window, and a refusal AFTER the removal would leave a run that ends in a refusal having destroyed something. So under `--execute` the order is fixed: fetch the mainline again and re-prove the landing, re-run the whole worktree judgement (branch tip read once more at its very end), remove the tree, scan the holders, delete the ref pinned to the judged sha. Nothing between the removal and the deletion touches the network; the only refusals possible there are the holder re-scan and the lease itself. The rules the capture enforces are the worktree removal rules in `SKILL.md`; a live-writer probe that cannot run (lsof missing, partial, or answering nothing) is exit 3, and `--no-writer-check` waives that one probe only. The run's own ancestors (the invoking shell) are exempt from that probe on the assumption that a foreground invocation's parents are waiting on it; a run backgrounded from a shell that keeps working in the tree defeats the assumption, so invoke it in the foreground.
